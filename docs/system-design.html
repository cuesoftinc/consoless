Consoless System Design

Go api/common owns every byte of data, Python makes every decision, and generated games run only on a separate play origin. api/generate writes the game, api/verify proves it runs, and the shared Kafka bus carries pointers between them. The full write-up is docs/system-design.md.

Who it's for

Consoless turns a prompt such as “a falling-block puzzle on a green handheld screen” into a game you can play in the browser, then keeps editing it by chat. It is for non-coders with game ideas, hobbyist developers who take over the code, classrooms, retro fans and open-source contributors. Stage 1 is retro and 2D games, Stage 2 adds 3D, and Stage 3 adds desktop installers.

The rules

Go only does CRUD.api/common is the only service that opens Postgres, Redis, blobs/ or the play bucket. It saves decisions; it never makes them.
Python makes every decision.Prompt policy, generation, moderation and the pass-or-fail verdict all happen in api/generate and api/verify.
Generated code never runs on our origin.Games load only from the play origin in a sandboxed iframe. The runtime never calls the API; scores travel by postMessage.
Pointers, not data.Prompts, code and reports live under consoless/compute/. Bus messages carry only ids, enums and refs.

Events on the shared bus

Lanes, envelope and limits come from the CueLABS shared-messaging contract. Every type starts with consoless., is validated against a schema in api/common/contract/, and is keyed by project id so one project's steps stay in order.
